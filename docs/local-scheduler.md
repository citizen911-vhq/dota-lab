# Локальное обновление каждые 4 часа

На Mac владельца установлен LaunchAgent `local.dotalab.analysis`.
Он запускает `node scripts/dota-local-scheduler.mjs` после входа в macOS.
Codex и вкладку сайта можно закрыть. Без входа пользователя, во сне и при
выключенном ПК выполнения нет. После пробуждения/входа выполняется один
просроченный цикл, а не все пропущенные циклы подряд.

Служба раз в минуту проверяет локальный API. Анализ запускает через 4 часа
после последнего завершённого обновления со здоровым сбором истории.
При ошибке сети или неуспешном сборе — повтор не раньше чем через 15 минут.
Обычные предупреждения о покрытии расписания не ускоряют цикл. Ручное
обновление тоже учитывается. Блокировки службы и приложения защищают от
параллельных запусков. Существующий сервер не останавливается; если порт
свободен, запускается локальный dev-сервер из того же проекта и с той же БД.
Сервер слушает только 127.0.0.1, публичного доступа эта настройка не создаёт.

Полный цикл `/api/analysis/run` обновляет историю, расписание, прогнозы,
затем запускает существующий отбор **виртуальных** ставок. Правила качества,
квоты API и защита от дублей не ослабляются. Реальных ставок нет.

Диагностика:

```sh
launchctl print gui/$(id -u)/local.dotalab.analysis
```

Состояние и следующий срок: `.sites-runtime/dota-scheduler/status.json`.
Лог сервера: `.sites-runtime/dota-scheduler/server.log`.
Лог службы: `~/Library/Logs/dota-lab-scheduler.log`.
Ключи берутся самим приложением из существующей локальной конфигурации;
их нет в LaunchAgent или статусе. Runtime-файлы исключены из git.

Остановка перед переносом на сервер:

```sh
launchctl bootout gui/$(id -u) "$HOME/Library/LaunchAgents/local.dotalab.analysis.plist"
```

Для постоянного отключения убрать именно этот plist из LaunchAgents и
отключить контрольную автоматизацию Dota Lab в Codex. Сохранённая надпись
о расписании в приложении — конфигурация, а не доказательство живого процесса.
На сервере нужен отдельный scheduler и перенос БД/секретов. Этот macOS
LaunchAgent не переносится автоматически; одновременно два независимых
эксперимента на локальной и серверной БД запускать не следует.
